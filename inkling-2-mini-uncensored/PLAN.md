# inkling-2-mini-uncensored: experiment log

Two uncensored edits of Inkling-2-Mini on the base recipe's engine and layout (`../inkling-2-mini/`, build
`r2inkfix-19c41d2ff` = llama.cpp master 225a5345b + two F16-mask patches). Test port 8102. Every row: config in
`configs/`, raw data in `runs/` (server logs `runs/server-<label>.log`, measurements `runs/ledger.jsonl`).
A/B rule: control / candidate / control, medians of 6 capped coding answers, one change per config.

## Targets and constraints
- Same targets as the base recipe: single user, 64k context, decode and prefill as close to the base as the edit allows.
- Memory: 12 GB card (desktop holds ~1 GB), gpu_run cap 44G (page cache counts).
- Quality: report KLD vs ggml-org Q8_0 (the best reference on disk), refusal probe, codeeval, needles at 32k / 62k.

## STATUS (2026-11-23)

Best: `serve.sh` default (`VARIANT=atomicchat`, AD-Q4_K, base layout, ub 96, 64k): 29.6 tok/s decode, 137 prefill at
8k, 24.1 decode at 32k, needles 3/3 at 32k and 62k, codeeval 8/8, refusal probe 20/20 answered, KLD 0.014 / 0.011.
Against the base recipe's unedited IQ4_NL: +2% decode, −6% prefill. Against the practical ceiling in THEORY.md
(~30.9 tok/s for this file's byte mix): 96%.

What limits it: the same ~23 ms per token of per-layer GPU overhead as the base (48 layer applications), plus the RAM
expert reads; on top, AD-Q4_K's core experts take 0.47 GiB more VRAM than IQ4_NL's, which costs the ub 128 compute
buffer and so ~6% prefill.

The question of which edit to ship is settled by measurement, not by tuning; three placement/ubatch levers on AD-Q4_K
were tried (ub 64, 96, 128 + no-op-offload) and ub 96 is the only one that is both faster and stable.

Remaining levers, ranked (estimated payoff × likelihood):
1. AtomicChat's smaller files (AD-IQ3_S 13.3 GB, AD-IQ2_M 8.7 GB): would free VRAM for ub 128 or the MoE cache.
   KLD on their card 0.0235 / 0.132 against 0.0115 for AD-Q4_K, so a quality trade. Needs a download (13.3 GB: owner's OK).
2. Build the base recipe's PR #32740 / MoE-cache / DSpark levers for this file: they need spare VRAM, which AD-Q4_K at
   64k does not leave; at 32k they might (base: +10–20% decode at 32k).
3. Merge AtomicChat's rank-1 LoRA into ggml-org's IQ4_NL (needs 3-D expert merging in `tools/merge_lora.py`): would give
   AtomicChat's edit at IQ4_NL's layout and ub 128 (prefill 145) without the 16.5 GB file. But a rank-1 edit of
   `ffn_down_exps` touches every expert, so all 24 down-projection tensors would be re-quantized to IQ4_NL without
   ggml-org's imatrix; that rounding error is not measured and could exceed the edit's own KLD (0.005).
